## プロダクト

OPEN DOOR TOKYO は、店舗を短い動画で撮影すると、入口の段差、ドア、通路、席、筆談などをQwen VLが整理し、利用者が来店前に確認できる日英Access Cardを作るWebアプリです。

`/Users/b/Documents/codex 2/open-door-tokyo`

主な画面:

- `/capture`
- `/review/[cardId]`
- `/c/[cardId]`

確認対象:

- `components/capture-client.tsx`

- `fixtures/demo-published.json`

## ユーザーからの確定要件

1. 日本人向けサービスなのに英語が多すぎる。画面は日本語を主表示にする。
2. 表現が分かりづらい。一般の利用者が一度で意味を理解できる言葉にする。
3. 段差高などは正確な実測でなく、映像からの参考推定でよい。
4. 重要なのは、車椅子、ベビーカー、目が不自由な人などが、店へ電話せず、行く前に状況を知り、自分で判断できること。
5. ChatGPT Images 2.0で作る統一ピクトグラム素材を使い、一目で何の情報がある場所か分かるようにする。
6. 「車椅子対応」「バリアフリー認定」のような適合・認定断定はしない。
7. AI参考推定は「約3〜5cm」「映像からの参考推定」「実測ではありません」のように明示する。
8. 英語は削除せず、言語切替または補助情報へ下げる。
9. 人間確認後に公開する既存ゲートは維持する。

## 依頼内容

現在の画面とコードを読み、以下を日本語で設計してください。

### 1. 読者が持ち帰る一文

プロダクト価値を、日本の一般利用者に分かる一文で確定してください。

### 2. 情報階層

capture、review、public cardの各画面について、最初の画面で見せるもの、詳細へ下げるもの、英語へ切り替えるものを明確にしてください。

### 3. 完成コピー

各画面でそのまま実装できる、短く明快な日本語コピーを提示してください。

- H1
- 補足文
- 主ボタン
- 状態名
- 推定表示
- 未確認表示
- 人が確認した表示
- 公開前の説明
- 公開カードの注意書き
- 地図掲載の説明

英語や技術語の大見出しは禁止です。Qwen、schema、agent traceなどは一般利用者画面では詳細欄へ下げてください。

### 4. 一目で分かる表示

次の6分類を、統一ピクトグラムと日本語ラベルで示す設計を作ってください。

- 車椅子
- ベビーカー
- 白杖・視覚
- 筆談
- 段差
- 入口幅

各分類には次の3状態だけを使います。

- 情報あり
- 参考推定
- 未確認

緑のチェックだけで「利用可能」と誤解させないでください。色だけに依存せず、文字と形でも状態を伝えてください。

### 5. 画像素材仕様

ChatGPT Images 2.0へ渡すため、6個のピクトグラムを一つの統一素材シートとして生成する具体的な画像プロンプトを作ってください。

- ピクトグラム自体には文字を入れない
- 2行×3列、各セル同じ余白、白背景
- 日本の公共サインに近いが公的認証に見えない
- 太く単純で、小さくても判別できる
- 車椅子、ベビーカー、白杖、筆談、段差、入口幅を混同しない
- ブランド色は濃紺、青緑、珊瑚色
- SVGやコード手描きへ置換しない

### 6. 実装優先順位

残り時間が短いハッカソンとして、効果の大きい順にP0、P1、P2で整理してください。

## 出力形式

- 先に結論
- 完成コピーは引用符で一字一句示す
- 抽象論ではなく、画面別の具体案
- 最大2,000日本語文字程度
- コードは書かない
- 最後に、誤認防止の確認項目を5つ
